# Agent instructions (Tinland)

Tinland is the macOS editor written entirely in Tin. It lives in its own repository; the language
and toolchain (compiler `tinc`, runtime, standard library, packages) are in
[usetin/tin](https://github.com/usetin/tin), and the documentation is in
[usetin/docs](https://github.com/usetin/docs).

## Setup and checks

```sh
git clone git@github.com:usetin/tin.git ../tin   # or anywhere: TIN=/path/to/tin
git clone git@github.com:usetin/tit.git tit      # project/ imports tit's ignore rules relatively
make build        # bin/tinland (macOS)
make test         # the suite: portable parts everywhere, editor and window on macOS
```

- `TIN` (Makefile) or `TIN_ROOT` (test scripts) point at the tin checkout; `../tin` is the default.
  The tin checkout builds `bin/tinc` from its checked-in seed, no Go or cc. The tit checkout must be
  `tit/` inside this repository: `project/` imports `tit/ignore` relatively.
- Tinland runs on macOS only. Linux CI runs the portable parts (ui layout, project ranking,
  terminal screen); the editor, window snapshots and GPU tests run on macOS.
- The VS Code extension lives in `vscode/`; its tests are `npm ci && npm test` there, with
  `TIN_VSCODE_COMPILER` and `TIN_ROOT` pointing at the tin checkout.

## Rules

- Keep the editor's design notes current: `ARCHITECTURE.md` says what each package is for.
- `icon/Tinland.icns` is generated by `tools/dev/tinland_icon.sh` (macOS with a GPU); do not edit it.
- The `tests/golden/` files are the expected output of the programs in `tests/programs/`; a change
  that alters them is reviewed like a test change (update the golden file in the same commit, and
  say why in the message).
- Style follows the Tin language: edition 1, tabs, one declaration per line. `../tin/tin fmt` formats.
